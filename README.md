# SBGATOOLS 使用手册

> **当前版本**: v1.4.21+118（当前工程版本；本次操作未构建 APK 或发布 Release）
> **当前更新条目**: v1.4.21 已随工程版本切换生效（下埋迁移至批量上传歌曲、按歌曲选择、歌曲成绩清除、默认 DX 百分比范围调整、LXNS CN1.56-C 数据同步、水鱼同步全角空格修复）
> 一款用于 maimai DX 游戏的功能票发放与存档修改工具。
> v1.4.16 的下埋与试用许可证流程已于 2026-07-20 完成实机验收。

## 快速开始

### 1. 导入许可证

首次使用需要导入许可证文件（`.sbl` 格式）：

1. 打开应用，进入**设置**页面
2. 点击**导入许可证**按钮
3. 选择许可证文件

> ⚠️ 许可证文件创建后 **1 小时内** 必须导入，超时将无法使用

### 2. 配置机台狗号

在设置页面填写机台狗号（clientId）。区域、店铺 ID、店铺名称和认证时间由 APP 执行 ALL.Net PowerOn 后自动获取并缓存，设置页只读显示当前获取到的信息。

> ⚠️ 机台狗号为必填项，格式为 11 位字符；如果 PowerOn 返回狗号失效，APP 会阻止后续 Title 通信。

### 3. 开始使用

应用底部有三个标签页：

- **发送功能票**：扫描二维码 → 自动登录 → 发送功能票 → 自动登出
- **获取账号数据**：“修改并上传”主开关关闭时仅获取数据；开启后在同一卡片内显示“批量上传歌曲”子开关，可选择普通自定义配置或批量上传歌曲流程
- **个人数据**：浏览已保存的账号、收藏品和歌曲数据，并使用查分器同步

操作步骤：
1. 点击**扫描二维码**或**手动输入**
2. 扫描/输入公众号生成的二维码或复制其网页链接（支持自动读取剪贴板）
3. 等待自动处理完成（处理中显示进度和实时日志）
4. 查看日志确认结果（支持导出诊断日志）

## 功能说明

### 时间同步与 PowerOn 状态

主界面左上角显示 NTP 时间同步和 PowerOn 的合并状态：

| 图标 | 颜色 | 说明 |
| -- | -- | -- |
| ✓ | 🟢 绿色 | NTP 同步成功，且 PowerOn 已完成本次实时认证 |
| ⏱ | 🟠 橙色 | 正在进行 NTP/PowerOn 检查，或已安全复用当日 PowerOn 缓存（可继续执行） |
| ✗ | 🔴 红色 | NTP 不可用、PowerOn 失败，或狗号失效 |

> 💡 应用启动时自动进行 NTP 同步和 PowerOn。NTP 会解析服务器原始时间响应并过滤高延迟/异常样本；PowerOn 会获取 `utc_time`、`client_timezone`、区域和店铺信息，并派生 Title 通信用的 `dateTime`。正式执行中若 NTP/PowerOn 遇到临时网络、5xx 或损坏/不完整响应，会在初次失败后按 2/4/4/8/12 秒最多重试 5 次；第 5 次重试仍失败才停止，明确 4xx 和狗号失效不会重试。实时成功响应额外要求 `utc_time` 与当前可信时间相差不超过 5 分钟，07:00 切日瞬间允许新鲜响应自然跨日；实时响应和当日缓存都会严格校验时区范围、正数认证时间，以及非空店铺/区域字段。同步或 PowerOn 检查期间不能点击执行或扫描二维码。

> 💾 PowerOn 缓存按“机台狗号 + Asia/Shanghai 07:00 游戏日”保存。同一游戏日内的有效成功记录会显示“PowerOn 使用当前游戏日缓存”，不会再次发送实时认证；跨游戏日首次启动才会重新认证。已安装用户打开升级后的应用时，本地数据库会自动从 v11 升级到 v12 并迁移历史缓存；即使曾因中断升级或早期开发构建留下不一致的缓存表，启动时也会自动核验和修复，优先保留可用的当前缓存。无需清除应用数据或重新填写狗号。

### 二维码处理

支持**扫描二维码**（需相机权限）和**手动输入**（支持自动读取剪贴板）两种方式。

> 💡 剪贴板既支持直接复制二维码字符串，也支持公众号生成的
> `https://wq.wahlap.net/qrcode/req/MAID...html?...` 网页链接。APP 会从网页链接路径的文件名提取
> `MAID...` 内容并补齐 `SGWC` 前缀；查询参数不参与二维码内容。

> 二维码有效期为 **10 分钟**，超时需重新获取

输入二维码后，输入框下方会显示剩余有效期倒计时，颜色随剩余时间变化：

| 颜色 | 含义 | 可提交 |
| -- | -- | -- |
| 🟢 绿色 | 剩余 ≥1 分钟，正常有效 | ✓ |
| 🟠 橙色 | 剩余 <1 分钟，临近过期 | ✓（请尽快提交） |
| 🔴 红色 | 已过期 | ✗ |
| ⚪ 灰色 | 格式无效或未输入 | ✗ |

> 💡 临近过期时倒计时变橙色提示，仍可提交但请尽快操作；过期后提交会被拦截并提示重新获取

### 功能票倍数

仅在「发送功能票」标签页可调整：

| 倍数 | 价格 | 安全性      |
| -- | -- | -------- |
| 2倍 | 1  | ✅ 安全     |
| 3倍 | 2  | ✅ 安全（默认） |
| 5倍 | 4  | ⚠️ 危险    |

> ⚠️ 5 倍功能票存在风险，请谨慎使用
> ⚠️ 4 倍和 6 倍功能票因游戏版本 1.55 起不再支持，已移除

### 发票等待时间

固定 20 秒等待，无需配置。计时从 **UserLoginApi 响应成功返回** 后开始，获取用户数据和库存检查会在等待窗口内完成，上传前只补足剩余等待时间。

执行日志中等待阶段统一显示为 `【步骤5】发票处理（等待x秒）...`；账号已有功能票并跳过发票时不显示等待日志。

### 许可证系统

- **普通用户许可证**：仅限许可证中列出的 UserID 使用，可使用全部功能（包括批量上传歌曲）
- **管理员许可证**：不限制 UserID，可使用全部功能
- **试用许可证**：仅允许绑定 1 个 UserID，从签发时刻起固定有效 `2880` 分钟（两天）；可以使用发票、获取账号数据和普通自定义修改上传等功能，但不允许使用批量上传歌曲。如需使用，请购买普通用户许可证
- 普通用户/管理员许可证支持永久有效和自定义限时有效；试用许可证的有效期不可修改
- 所有许可证创建后仍须在 1 小时内导入；试用许可证的 1 小时导入时效不会延长其两天有效期
- 执行时会在二维码解析后验证许可证、用户权限和可信网络时间新鲜度
- 导入/重新导入/更新许可证时按钮在系统文件选择器活动期间自动禁用，避免重复触发导致 “File Picker is already active” 报错

### 自动更新

进入**设置**页面点击**检查更新**，也可开启**自动检查更新**（每次打开应用时自动检测新版本）。

更新检查、APK 下载和远程公告均使用设备系统信任的 TLS 证书链；证书无效或未受信任的 HTTPS 拦截会被拒绝。自建下载源证书异常时，已获取下载地址的更新会自动回退至 GitHub。

手动检查发现更高版本但该 Release 尚未提供有效 APK 时，设置页会明确显示“新版本安装包尚未上传，请稍后再试”，不显示下载按钮，也不会误报“已是最新版本”或沿用上一次检查的旧安装包地址。自动启动提示仍只在新版 APK 已可下载时出现。

v1.4.17 使用标准 `cdn.jsdelivr.net` 作为远程公告主源；一次完整获取（请求、正文和公告 JSON 校验）失败时先重试同一主源一次，重试仍失败才回退 `raw.githubusercontent.com`。该有限重试只用于可安全重复的公告读取，不会放宽 TLS 校验；HTTP 200 的旧 CDN 缓存无法由客户端识别为错误，因此不承诺实时刷新。公告在后台获取后通过主页图标和未读角标查看，不会在启动时强制弹窗，也没有设置页历史入口。长时间下埋不会依赖一次性 30 分钟快照，任务会在安全边界按需续期可信时间；下埋配置支持目标版本多选和白谱难度，白谱只按 standard/DX 各自实际存在的谱面纳入。上述行为已随 v1.4.17+114 定版。v1.4.18+115 在此基础上加入按人工清单解锁乐曲、Master（紫谱）和 Re:MASTER（白谱）；手动输入仅解锁乐曲本身，白谱清单可为空；userdata 分类新增默认关闭的“不更新游玩日期”开关，保护当日首次游玩相关日期，普通上传与下埋上传均生效。下埋 DX 百分比表示本次成绩的连续可达区间；0%/100%对应两端；历史成绩的 DX 分不再参与清理进度判断。构建器仍会验收本次实际 achievement、DX 和 combo，无法满足配置时安全停止，绝不上传越界成绩。查分器同步修复了 `musicId=11422` 的空标题遗漏：水鱼使用官方 `U+3000` 全角空格标题，落雪使用外部 `id=1422`、`type=dx`，不臆造正式歌名。以上为历史版本行为；当前工程版本以本文顶部和 `pubspec.yaml` 为准。

自建下载源仅支持 IPv6。下载前会检测当前 IPv6 连通性；无 IPv6 时会跳过自建源并直接使用 GitHub，避免无效等待。

### 更新公告

版本更新后首次打开应用时，会自动弹窗展示更新内容。跨多版本升级时，弹窗会累积展示从上次查看版本之后到当前版本的全部更新内容，不再遗漏中间版本。

### 日志与诊断导出

历史版本的 APP 简要操作日志只显示流程、结果、错误等运行事件，不重复列出配置状态摘要；当前工程的三条流程边界格式为：发票开始 `========== 开始发票处理 ==========`、修改账号数据开始 `========== 开始修改账号数据 ==========`、批量上传歌曲开始 `========== 开始批量上传歌曲 ==========`，成功完成均为 `========== 操作完成 ==========`。批量上传歌曲开始时不会额外插入单独的“批量上传歌曲配置”标题日志，但批次/任务明细仍会保留。每条导出日志仍会标注任务、会话和批量上传歌曲批次上下文。详细导出日志会包含本次实际使用的机厅配置、自定义数据、图片加载和主题设置、自动更新、许可证、可信时间、PowerOn 以及流程运行状态。当前工程将 UserLog/UserAll 按相同批次成组保留最近 10 批并附带校验值；第 11 批进入时同时淘汰最早一批的两种载荷，避免长时间批量上传歌曲任务无界占用内存。

当前工程 v1.4.20+117 继续包含自 v1.4.19+116 起实施的批量上传歌曲概率性静默丢弃最低规避：新会话完整音乐数据已经获取成功但上一批成绩仍未生效时，不再重复读取音乐数据，而是根据当前最新 baseline 重新随机生成仍未达标成绩；同一目标集合从首次上传起最多执行 5 轮，只有连续 5 轮整组均无一首生效才中断并提示保存完整诊断日志。若一轮只有部分成绩生效，后续会保留已生效项并按新的待处理集合重新计数。该行为用于避免任务被单次随机结果卡死，不代表服务端丢弃根因已经确认。

详细网络日志会记录 GameClient、LXNS 和 Cookie 的实际请求、响应、解析失败及传输异常。按诊断用途，LXNS 的 URL、请求/响应头、Cookie、错误信息和正文不做脱敏；单次正文最多采集 10 KiB，并同时记录总大小、已采集大小和截断大小。日志导出仍通过日志面板的导出按钮保存为 `.txt` 文件。

### 获取账号数据

第二个标签页以“修改并上传”（默认开启）为主开关。“批量上传歌曲”（默认关闭）不是独立卡片，而是在主开关开启时于同一卡片内显示的子开关：

- **主开关关闭**：隐藏并清除批量上传歌曲子开关；获取数据 → 直接登出（仅更新本地数据，不修改存档）
- **主开关开启、批量上传歌曲关闭**：获取数据 → 普通自定义配置 → 上传存档 → 登出
- **主开关开启、批量上传歌曲开启**：仅普通用户/管理员许可证可用；扫码或手动提交 → 登录并获取完整账号数据 → 打开批量上传歌曲配置页 → 选择目标范围、难度和成绩条件 → 查看已达标/待上传进度 → 分批处理 → 续关回验

试用许可证下仍会显示“批量上传歌曲”子开关及购买说明，但开关保持关闭且不可操作；即使切换许可证后残留了旧的开启状态，提交路由和执行服务也会阻止试用许可证进入批量上传歌曲流程，不影响普通自定义数据流程。

存档上传流程已按 SDGB 1.55 DLL 等价逻辑迁移：登录后构建 `UserLog` 与 `UserAll`，先上传 `GetUserNewItemListApi`，再上传 `UpsertUserAllApi`。上传存档的 50 秒等待同样从 UserLoginApi 响应成功返回后开始计时；普通单会话流程沿用既有入口时间门禁，并在等待结束后刷新实际上传时刻相关字段。批量上传歌曲则在每批 50 秒等待结束后按需续期可信网络时间，并在双 mutation 前用 2 分钟 reserve 确认接下来窗口仍有效，再刷新上传时刻字段；UserLog 与 UserAll 之间不插入 NTP 或其他网络动作。执行日志先显示 `【步骤6】上传数据（等待x秒）...`，随后依次显示 `上传 GetUserNewItemListApi...` 和 `上传 UpsertUserAllApi...`。`playSpecial` 随机值按 DLL/.NET 的 signed int32 语义发送，避免高位随机值被错误当作 unsigned 正数导致服务器 HTTP 500。

userdata 分类新增“不更新游玩日期”（默认关闭），界面说明固定为“关闭后不影响当日集章以及上机信息展示”。开启后，UserLog/UserAll 的 `lastLoginDate` 与 `eventWatchedDate` 保留上传前账号值，`lastPlayDate` 仍按本次模拟游玩时间更新，`userPlaylogList.loginDate` 也不回拨，继续表示本次模拟登录时间；这样真机在当天首次游玩时仍能正确进入登录集章和信息展示流程。普通上传与批量上传歌曲均使用同一保护语义。该开关只对当前执行有效，任务完成后随其他自定义数据清空。

#### 批量上传歌曲

批量上传歌曲是普通用户许可证和管理员许可证专属功能，试用许可证不允许使用；如需使用请购买普通用户许可证。配置页的操作模式互斥：**批量上传歌曲**用于把未达到目标的标准/DX非宴会场谱面分批写入目标成绩；**歌曲成绩清除**不使用批量上传歌曲的成绩配置，而是把已有成绩清为脚本规定的0分字段。登录并获取完整账号数据后才打开配置页；按版本选择时目标来自完整歌曲目录，因此账号从未游玩、`userMusic` 中不存在的谱面仍可能纳入批量上传歌曲；按歌曲选择时只处理多选器明确确认的 `musicId`。

歌曲成绩清除只处理当前账号**完整 baseline 中已经存在的 `(musicId, level)`**，不会为未游玩谱面生成普通的 0 分记录，也不会从目录补造清除目标。每条清除成绩严格写入 `achievement=0`、`comboStatus=0`、`syncStatus=0`、`deluxscoreMax=0`、`scoreRank=0`、`extNum1=0`、`playCount=1`；仍使用真实 LXNS 物量、全 Miss timing、真实计分和 Playlog 构建链路。LXNS 明确返回 HTTP 404 时跳过整首歌曲并保留原成绩，其他缺失、类型错误或不一致均安全停止。

配置页的“目标选择方式”是互斥的：

- **按版本选择**：保留原有版本多选语义，版本以倒序双列展示，多个版本取并集并去重；standard/DX 按当前完整 musicId 对应谱面类型的 `difficulties.<type>[0].version` 判断，不跨类型回退。
- **按歌曲选择**：通过歌曲多选器明确指定一个或多个 standard/DX 非宴会场 `musicId`。只处理这些明确 ID，不会因为歌曲所属版本扩展到同版本其他歌曲，也不会把标准谱和 DX 谱按 `musicId % 10000` 互相串联；歌曲模式不设置收藏歌曲选择器的 30 首上限。

批量上传歌曲模式会把用户选择的难度（绿/黄/红/紫/白）应用到每一个目标歌曲。白谱只从实际存在性目录构造，standard/DX 按完整 musicId 分别判断；账号未游玩但目录明确存在的白谱仍会纳入，若静态目录暂时滞后而本次完整 baseline 已有同一 musicId 的 level 4 行，则以该真实记录兜底，不会为不存在的白谱生成成绩。该模式的版本/歌曲、难度、combo、sync 均不预填且必须手动选择；四个数值输入框同样保持空白，但可分别独立留空：achievement 下限在“无、FC、FC+”时默认 `1000000`，在“AP、AP+”时默认 `1005000`，上限始终默认 `1010000`；deluxscore 下限/上限默认 `75%`/`90%`。achievement 下限接受 `0~1010000` 的整数，上限接受 `1000000~1010000` 的整数，且上下限必须至少相差 `2500`；选择 AP 时下限还必须不低于 `1005000`，选择 AP+ 时上限必须为 `1010000`。DX 百分比支持 `0.00%~100.00%`、最多两位小数（如 `98.65%`），表示本次实际 achievement + combo 下连续可达 DX 区间的位置，`0%`/`100%` 分别为该区间两端。每张谱面随机取基点后都在该局真实可达区间内映射并正向验收，因此随机目标和最终上传的 achievement、deluxscore 都处于对应条件允许的范围内。

历史 `userMusicDetailList` 的 achievement、comboStatus 与 deluxscoreMax 是彼此独立的历史高值，不能证明来自同一局；因此 deluxscore 不参与批量上传歌曲进度、达标筛选或回验。页面底部仅按 achievement、combo、sync 预览，不为整版目标读取谱面物量。实际构建批次时才为待上传谱面按需读取物量，以生成真实 playlog。批量上传歌曲任务会合并同一歌曲的多难度读取，并将物理 LXNS 请求串行限速；单个逻辑谱面读取的通信异常、429/5xx、空响应、查询内容损坏与 difficulty/notes 缺失、物量合计矛盾或非法等暂时残缺结构共享一个 5 次重试预算，结构异常会先失效坏缓存，五次等待为 2/4/4/8/12 秒，整个读取合计最多 6 次物理请求。宴会场属于本地明确不支持的目标，不会重试。

普通“修改并上传”配置页中的歌曲资料和谱面物量也共用同一个任务级 LXNS 协调器：同一歌曲的 metadata 与 notes、多个难度只会复用一份真实响应。换成另一首歌曲时会先清空上一首的难度，待新歌曲资料确认后再选择谱面；Achievement、Combo、DX 和判定等细节修改只使用当前行已经验证的物量快照，不会重新查询 LXNS。交互预览若从成功响应中明确发现目标难度不存在，会保留歌曲缓存并立即提示不可用，不按暂时残缺反复刷新；正式上传或批量上传歌曲 fallback 仍会为可能暂时残缺的上游结构执行有限重试。可恢复的网络/HTTP/解析错误和其他暂时残缺谱面结构共享同一个 5 次重试预算，而不是各自重试；初次请求加 5 次重试合计最多 6 次物理请求。用户返回、取消或执行保护丢失导致配置页关闭时，协调器立即停止后续排队/退避请求，不会让后台 LXNS 重试与随后上传并行。明确 4xx、业务拒绝和不支持的宴会场等本地永久约束仍会失败。

两组范围都会在输入时实时检查：achievement 下限越界或选择 AP 时低于 `1005000`，固定在下限端提示；achievement 上限越界或选择 AP+ 时不为 `1010000`，固定在上限端提示；下限高于上限或差值不足 `2500` 时，则按最后编辑的端点给出方向性提示。留空端仍按上述动态默认值参与比较，修正后提示立即消失；点击“开始批量上传歌曲”时还会再次校验并阻止无效范围提交。目标选择方式为互斥的按版本/按歌曲 ChoiceChip；难度、combo、sync 与范围卡片按左右对称的标准布局排列，范围错误使用整行宽度显示且不挤压左右输入框；批量上传歌曲进度卡位于全部配置项之后的页面底部，用户从上到下完成设置后可直接查看进度；360dp 宽度下较长标签会自动缩放，完整错误提示也不会挤破对称卡片。

批量上传歌曲对已有成绩仍按 `无 < FC < FC+ < AP < AP+` 判断是否达到所选 combo 等级，但新生成成绩必须精确保持用户选择的 combo，不会为满足 achievement 或 DX 范围自动升级或降级。构建器先在 achievement 窗口内求得 combo 精确的基础判定，再把 Tap/Hold/Touch 的普通 Critical 逐个变为 Perfect；Slide Critical 固定保留，此变化不改变 achievement 或 combo，因而形成一段每个整数都真实可达的连续 DX 区间。随机百分比会映射到该区间并由正向计分验收；若随机 achievement 锚点不能得到合格基础成绩，只在当前 achievement 窗口内有限尝试中点、端点、四分位以及 AP 的 `1005000`/`1007500`，不会把 DX 改回理论 DXMax 百分比。所有候选仍不合格时会在上传前安全停止，绝不上传越界成绩。

v1.4.20 的自动 Playlog 改为严格两阶段。选择难度并取得 LXNS 五类 Note 物量后，APP 先预计算各类判定的整数计分画像；Achievement 全程使用 DLL 同式的合成整数分子，最后才统一截断，不会把大物量谱面单 Note 低于 `0.01%` 的损失提前舍入。确认 Achievement 与 Combo 后，第一阶段只生成满足 Combo 的基础 Playlog：目标低于 `505000` 时从低分端加算，高于 `505000` 时从 `1010000` 扣算，恰好半分才比较两端状态估算；精确命中优先，不能命中时只接受已证明的最近合法值。Tap/Hold/Slide/Touch 四类和 BREAK 的判定比例是软目标；目标分数越高，非 CP/P 判定越由 Great 主导，Good 与 Miss 作为接近的少量尾部，目标 loss 已经迫使出现的 Miss 才会保留，且按 Note 类型分散。该自然度目标随 Achievement/Combo 动态计算，不设置固定 Miss 上限，也不参与硬性的分值、Combo、DX 可达性证明。真实化 canonical 判定始终固定 `slidePerfect=0`，优先保证精确分值、Combo 和后续 DX 可调空间。

基础 Playlog 完成后，Achievement 与 DX 输入框会先回填该 Playlog 的正向真实值。用户再修改 DX 时，第二阶段只把同一基础 Playlog 中 Tap/Hold/Touch 的 CP/P 按物量容量重新分配：每个可重映射 CP→P 恰好降低 1 点 DX，Slide CP 固定保留，Achievement、Combo、BREAK P75/P50 与三个 Great 内档以及其他判定均不改变；目标超出当前连续可达区间时回填最近边界。DX 编辑期间不会被旧结果覆盖，键盘确认或失焦后同步完成该映射，不会再次运行 Achievement 全量搜索。用户手动填写的判定明细不会被自动重排；真实化开启时 Slide P 始终固定为0。关闭真实化时仍遵守 Slide CP/P 互斥：Slide CP 非0时 Slide P 固定为0，只有 Slide CP 为0时才可编辑 Slide P；Slide P 非0时 Slide CP 控件锁定。重新打开已有配置时会完整恢复 Tap/Hold/Slide/Touch 各 5 档与 BREAK 8 档共 28 个判定值，LXNS 物量返回后只正向校验。已保存的自动结果还会从原 Final 中仅将 Tap/Hold/Touch 的普通 P 还原为 CP 来恢复 canonical Base，因此无需重跑 Achievement 求解即可继续编辑 DX；Slide CP、BREAK 和其他判定保持原样。最终上传直接复用这 28 个已计算或手填的 canonical 判定，最后才按 `dispJudge` 转换显示字段，不会上传前再反推另一份分布。此项是 Playlog 真实性优化，不代表已经定位或修复服务端概率性静默拒绝。

AP+ 的真实 achievement 固定为 `1010000`。批量上传歌曲最终生成 `1010000 + AP+` 且未显式覆盖 `extNum1` 时，会写入 `max(历史 extNum1, 0) + 1`；没有历史成绩时写入 `1`。如果用户选择的是 AP，新成绩不会自动提升为 AP+，也不会因此增加 `extNum1`。

批次日志会用 `musicid{id}-{歌曲名}-{难度}` 标识谱面，例如 `musicid11272-约束-绿谱`。“本批上传目标”只显示这些目标身份，不附带当前分数；“本批生成成绩”会逐项显示 achievement、deluxscore、combo、sync 的 `旧值→新值`，已有历史成绩和未游玩谱面都能直接核对本次变化。

开始执行后，进度栏会显示当前批次和真实阶段，包括构建上传数据、`上传数据（等待x秒）`逐秒倒计时、分别上传 UserLog/UserAll、同步本地数据、登出、续关及下一会话回验。配置确认后的百分比按已回验谱面数与当前批次阶段连续计算，多批次续关或同批重新生成时不会回退到较低百分比；最终登出阶段约为 95%，只有流程严格成功后才显示 100% 完成。每轮 baseline、配置页返回、零目标完成和 confirmed 登出后的续关前会在可安全暂停边界按需续期可信时间；NTP 临时通信失败会在进入上传前按 2→4→4→8→12 秒最多重试 5 次，在取得可信时间前本批两段上传都不会发送，预算耗尽则安全收尾。

- 两种操作模式都每批最多处理 3 条谱面；每个会话都会重新下载完整账号 baseline，不能沿用首批数据。歌曲成绩清除还会用初始 baseline 与当前 baseline 的每谱成绩贡献差值完整回验 userdata 聚合；不足3条时沿用 `11272:0` 虚拟长期成绩/Playlog 占位，但该占位不是清除目标。
- 上传固定按 `GetUserNewItemListApi → UpsertUserAllApi` 单次发送；第一段未明确成功时不会发送第二段，状态变更请求结果未知时也不会重试。
- 可信时间硬上限仍为 30 分钟；50 秒等待结束后，双 API 开始前要求可信时间至少再剩 2 分钟。UserLog → UserAll 之间及两段发送前/返回后只做同步本地授权检查，不触发 NTP。
- 上传请求被接受后先登出，再通过续关进入下一会话；只有 confirmed 登出才允许继续，新会话会用新 token/loginId 和完整 baseline 回验上一批成绩。若完整音乐数据已成功取得但本轮成绩未全部生效，APP 不会重复读取同一份服务器状态，而会保留已生效项，并立即使用当前最新 baseline 只为仍未达标谱面重新随机生成成绩；清除模式在 404 时跳过整首歌曲并保留原值，不把删除曲误判为 mutation 失败。
- 续关使用 PowerOn `authTime`、本次新生成的 `loginDateTime`、上一会话响应 token，并接收新的 token/loginId。首批成功登录后，后续续关不再受初始二维码 10 分钟有效期限制。
- 只有服务器明确确认登出时才删除 Session 并继续；明确上传失败、续关失败或登出无法确认都会保留必要 Session 并中断。成绩回验未生效时，同一排序后的目标集合从首次上传起总计最多执行 5 轮；部分生效、目标集合变化或整批成功会重置计数。只有连续 5 轮整组均无一首生效才中断，并提示保存完整诊断日志发送给开发者。每轮都重新生成新的成绩 payload，单次 UserLog/UserAll 请求本身仍不会自动重发。

**本地数据同步**：存档上传成功（`returnCode=1`）后，APP 会自动用最终 UserAll 数据增量更新本地数据库至上传后的最新状态。此前数据页展示的是上一次获取时的状态（会落后一次），现上传后立即同步——userData 全量替换，角色/收藏品/地图/集章卡/歌曲成绩按主键增量更新（收藏品移除模式会删除对应记录）。同步失败不影响主流程，仅记录警告日志。

### 操作反馈

应用内所有提示消息（如"已保存"、"已导入"、"二维码已过期"等）新显示时会立即替换上一条提示，避免快速连续操作时旧消息滞留堆积。

### 取消操作

处理过程中可点击**取消**按钮，应用会在下一个安全检查点停止主业务并尝试登出；如果服务器未能明确确认登出，Session 会保留，供下次手动执行时继续收尾。

如果取消发生在登录请求已经发出、但响应返回后的保护检查窗口内，APP 会先检查这次客户端是否已收到 Cookie；已收到时先保存 Session，再进入登出收尾，避免服务器已登录而本地没有可供下次清理的会话。

自定义数据和批量上传歌曲配置页的返回只会退出当前配置页，不会关闭主页面。取消或前台保护丢失时，如果配置页上方仍打开了提示对话框或选择器，APP 会先关闭这些临时页面，再安全退出配置页；未确认的歌曲多选、旅行伙伴选择都会保留原有配置，不会被当作确认空选而清空。

### 当前执行保护

开始处理前，APP 会先确认 Android 前台服务确实已经启动；如果服务实际启动失败，这次业务不会继续登录、发票或上传。Android 13 及以上即使没有授予通知权限，APP 仍会尝试启动服务，通知权限只影响常驻通知是否可见，不等于服务启动失败。

APP 在前台执行时会保持当前页面不自动息屏。按 Home、切换应用或锁屏后，屏幕可以正常关闭，但前台服务会继续维持当前执行所需的 CPU 运行；返回 APP 前台时会重新为当前窗口应用屏幕常亮标志。这里不承诺绕过系统网络限制，临时断网由下述网络恢复策略处理。

本功能只保证 APP 进程仍存活时的当前执行。系统强制杀掉 APP 或用户从最近任务划掉 APP 后不会自动续跑，用户下次手动执行时，APP 会使用数据库中保存的 Session 尝试完成旧会话登出。

### 异常退出自动登出

登录成功后，APP 会先确认 Cookie 已保存到本地数据库，再进入后续业务。登录请求已经发出但在取消/保护丢失时才返回的场景，也会在发现 Cookie 后先尽力保存 Session 并进入登出收尾。只有服务器明确确认登出后才删除该 Session；登出请求已发出但无法验证、登出失败或 APP 意外关闭时都会保留 Session，供用户下次手动执行时尝试收尾。

这套机制用于清理账号会话，不会自动恢复已经中断的发票或存档上传。

## 常见问题

### Q: 提示"二维码已过期"

**A:** 二维码有效期为 10 分钟，请在公众号上获取新的二维码。

### Q: 提示"许可证不允许操作此用户ID"

**A:** 当前许可证未包含您的 UserID，请联系管理员获取授权或使用管理员许可证。

### Q: 提示"许可证导入时效已过"

**A:** 许可证文件创建后 1 小时内必须导入，超时请联系管理员补发新许可证。

### Q: 提示"许可证已过期"

**A:** 许可证已超过有效期，请联系管理员续期或重新获取。

### Q: 为什么试用许可证不能开启批量上传歌曲？

**A:** 试用许可证用于体验除批量上传歌曲外的其他功能，仅绑定 1 个 UserID，签发后固定有效 2880 分钟。批量上传歌曲能够节省大量清谱时间和费用，是普通用户许可证的付费功能；如需使用，请购买普通用户许可证。

### Q: 提示"可信网络时间不可用"

**A:** 如果可信时间已过期或剩余时间不足，批量上传歌曲会在 baseline、配置返回和上传前等安全边界自动刷新；NTP 临时断网、无合格样本或响应异常会按 2/4/4/8/12 秒最多重试 5 次，重试期间可取消，第 5 次重试仍失败才进入安全收尾。应用不会在 UserLog 与 UserAll 两段上传之间插入校时或重发请求。

### Q: 提示"PowerOn 狗号失效"或"PowerOn 认证失败"

**A:** 狗号无效、过期，或当前网络无法完成 ALL.Net PowerOn。请确认设置页填写的是有效 11 位狗号；启动页会优先使用当天 07:00 游戏日内的成功缓存，没有可用缓存时暂不开放执行入口。正式执行已经开始后若需重新 PowerOn，临时网络、5xx 或损坏响应会按 2/4/4/8/12 秒最多重试 5 次，狗号失效等明确拒绝立即停止。

### Q: 启动后反复显示“PowerOn 认证成功（缓存保存失败）”怎么办？

**A:** 同一游戏日内这不是预期行为。旧安装数据库曾使用历史缓存表名，升级后的应用会自动完成 v11→v12 迁移，并在每次打开本地数据库时修复遗漏或不一致的缓存表；已有的可用当日成功认证会被保留，下一次启动应显示“PowerOn 使用当前游戏日缓存”。跨越 07:00 游戏日、变更机台狗号，或原本没有有效成功缓存时，重新实时认证则是正常现象。若完成升级后同一游戏日仍持续出现该提示，请导出诊断日志反馈；不要先清除应用数据。

### Q: 从自定义数据页或批量上传歌曲配置页返回后黑屏怎么办？

**A:** 返回、取消和前台保护丢失都应只退出当前配置页并回到主页面；若当时打开了选择器或提示框，会先将其关闭。取消旅行伙伴选择也不会清空已配置的角色。若更新后仍复现黑屏，请保留操作步骤和导出的诊断日志反馈。

### Q: 发票失败

**A:** 可能原因：

- 账号内已存在功能票（应用会自动跳过）
- IP 地址被服务器限制
- 网络连接问题

### Q: 存档发送失败

**A:** 可能原因：

- 网络连接不稳定：正式执行中的 Title、NTP、PowerOn 和 LXNS 安全读取遇到 Socket/超时、TLS/HTTP 协议异常、HTTP 408/425/429/5xx、空响应或可恢复的损坏内容时，会在初次请求失败后按 2→4→4→8→12 秒最多重试 5 次（总等待 30 秒）；等待期间每秒检查取消与执行保护，第 5 次重试仍失败才结束当前流程
- 单次或偶发的 Title API 空响应通常只是服务器繁忙或接口高负载，不会判定 IP 被封。任一 Title API 的单个逻辑读取只有在初次请求和 5 次重试共 6 次请求全部为空时，才把当前公网 IP 记录到疑似软封禁列表；期间出现任意实际响应或传输失败都不满足判定条件，连接重建或 Session 清理也会清空相关证据
- 登录、发票、登出、UserLog/UserAll 上传等会改变服务器状态的请求只发送一次。登录/登出通过用户预览、发票通过功能票库存、已接受的批量上传歌曲批次通过下一会话完整 baseline 进行最终一致性对账。批量上传歌曲已经成功取得完整音乐数据但上一批成绩仍不存在时，不再重复读取同一状态；APP 会按当前 baseline 重新随机生成未生效目标，连续 5 轮仍失败才中断并提示导出完整诊断日志。这里重建的是新 payload，不是重发同一个 mutation。若流程已被取消或前台保护已经丢失，登出后仍至少尝试一次预览确认，但首次确认失败后不会继续等待
- 二维码成功响应内容损坏、分页 `nextIndex` 非法或重复时在正式执行中同样按安全读取恢复；分页超过 200 页时使用不可重试的熔断立即停止。必要字段持续缺失或列表长度矛盾时不会拿缺失/截断数据继续发票或上传
- 网络等待可能跨越可信时间新鲜期或 07:00 游戏日；恢复后会在下一允许网络的安全边界、进入 mutation 序列前重新续期可信时间并确认当前游戏日 PowerOn，不会继续使用长等待前的旧 AuthTime，也不会在 UserLog/UserAll 两段之间插入校时或 PowerOn
- IP 地址被封禁

> v1.4.5 起已修复一类旧版本随机失败：旧逻辑在 `playSpecial` 随机到高位 32-bit 值时会以 unsigned 正数上传，可能触发 `UpsertUserAllApi` HTTP 500。该问题与系统时间同步无关，表现为“有时成功、有时失败”。

### Q: 歌曲成绩上传的"Playlog 真实化"是什么？

**A:** 开启后配置页会从 LXNS 获取谱面物量，并按 DLL 计分规则准备 playlog 判定；普通上传直接复用配置页已保存的判定值，不在上传前重新求解。输入 achievement 与 comboStatus 后先生成基础判定，随后只用 Tap/Hold/Touch 的 CP/P 调整 DX，Slide P 固定为0且不进入可达区间；achievement 离散不可精确命中时，仅在能够证明全局最近值后回填真实值。若快速搜索只得到一份正向有效的近似结果，APP 会用该误差建立目标两侧的闭窗口，再按普通 Note、BREAK 普通分和 BREAK 奖励分三个 DLL 整数格点核查是否存在更近值；只有窗口覆盖完整或已经找到精确结果才会采用。资源上限不足时当前目标不会采用未证明结果；批量上传歌曲若继续，只能把配置范围内另一个值作为新目标重新求解，不能把新目标的精确结果说成原目标的最近值证明。手动修改 Tap/Hold/Touch 各 5 档、Slide 除 P 外的可达档位与 BREAK 8 档时会正向复算出精确 achievement；关闭真实化时 Slide P 仅在 CP=0 时可编辑，CP>0 会固定 P=0，P>0 时 CP 控件锁定。AP/AP+ 边界按游戏实际规则处理：所有谱面都有 BREAK，AP 必须包含至少 1 个 Break Perfect，1010000 且全 Critical 会变成 AP+。若账号 `dispJudge` 为 Type1 系列，普通键 Critical 会在最终格式化时合并显示到 Perfect，BREAK 的 Critical/Perfect 仍保持分开。

v1.4.20 的配置页自动算法会在 Achievement/Combo 基础阶段按 Tap/Hold/Slide/Touch/Break 五类物量共同分配判定，不再先把低判定集中填到 BREAK；DX 阶段只在同一基础解内重映射 Tap/Hold/Touch 的 CP/P，Slide P 固定为0，不再按固定 Note 类型顺序重新求整份判定。各类判定率只要求大致接近，BREAK 可保留更大偏差以优先保证真实可达的 Achievement、DX、Combo、Rank 和谱面物量；遇到离散分值无法精确命中的目标时，仅在已证明最近值的情况下回填最接近的合法实际值。手动填写 Tap/Hold/Touch 各 5 档、Slide 除 P 外的可达档位与 BREAK 8 档仍完全按输入正算，不经过自动基础求解；自动和手填的保存结果都由最终上传直接复用。

v1.4.20 的大物量谱面响应性优化会把配置页第一阶段 Achievement/Combo 基础 Playlog 与批量上传歌曲批次求解放到后台计算。歌曲传分页确认 Achievement 与 Combo 后显示“正在计算基础成绩...”，短暂停顿输入后只计算并回填这一行最新目标；换谱、删行、改为手填判定、关闭真实化或退出页面后，较早结果不会覆盖当前内容。DX 第二阶段只是缓存基础解上的 Tap/Hold/Touch CP/P 同步映射，Slide P 固定为0，确认输入后不再启动完整后台搜索。计算尚未完成、失败、未证明最近值或结果指纹过期时，保存会留在配置页并提示。普通上传直接格式化配置页保存的判定值；批量上传歌曲仍在后台求基础成绩并复用同一基础解映射 DX，等待期间界面、进度和取消操作可响应。已经开始的单次 isolate 会自然结束，但失活结果不会继续下一首或上传。

关闭 Playlog 真实化时仍使用旧兼容模板，但 ComboStatus 下拉变化会立即按谱面类型刷新判定明细：标准谱不写入 Touch 判定，DX 谱保留 Touch CP=1，并按所选 AP/AP+/FC+/无等状态切换边界档位。最终保存构建直接复用配置页当前的 28 个判定值，不再在构建阶段按 ComboStatus 或谱面类型二次修改。

v1.4.14 起，配置页成功取得并校验谱面物量后，最终构建会复用同一份物量，不再为同一谱面强制发起第二次 LXNS 请求。若物量仍在加载、缺失、校验失败或与当前歌曲/难度不匹配，保存会留在配置页并提示；从未取得有效物量时，真实化仍会阻止构建。导出的完整诊断日志会记录实际发生的 LXNS 请求及失败原因，命中已验证物量快照时不会伪造或额外发起请求。

### Q: 水鱼查分器同步是什么？如何使用？

**A:** 数据页账号子页在账号预览窗和游玩统计窗之间提供"查分器同步"卡片，可将本地保存的账号歌曲成绩上传至水鱼查分器（diving-fish maimaidxprober），用于记录游玩成绩、输出达成进度和推分建议等。

- **首次使用**：点击"水鱼同步"按钮，弹出对话框引导输入 Import-Token（在水鱼查分器网站 https://www.diving-fish.com/maimaidx/prober/ 登录后，于"编辑个人资料"中生成）。Token 保存在本地数据库中与 UserID 对应，多账号互不影响。
- **后续同步**：绑定 Token 后再次点击会弹出确认对话框，显示将上传的记录数，提供"取消"、"更换Token"、"立即同步"三个选项；确认同步后按水鱼官方 API 要求转换本地成绩（达成率/10000、ComboStatus/SyncStatus 枚举映射、SD/DX 类型判断）并上传到 `POST /api/maimaidxprober/player/update_records`。
- **更换Token**：在同步确认对话框中点击"更换Token"按钮，会重新弹出 Token 输入对话框。
- **解除绑定**：在设置页删除对应账号数据，会同步删除该账号的水鱼 Token 绑定记录。
- **过滤规则**：宴会场歌曲（musicId≥100000）水鱼不支持，自动跳过；本地目录中不存在的歌曲或没有可确定标题的未知条目也跳过。`musicId=11422` 是明确存在但本地名称为空的例外，使用水鱼官方目录中的 `U+3000` 全角空格标题上传，不能改成 `1422`、"未知"或猜测正式歌名。musicId 11272（"約束"）不过滤——它本身是真实歌曲，项目内部用其 level 0 作为虚拟占位 playlog 不影响查分器同步的真实成绩。
- **特殊处理**：musicId 383（"Link(CoF)"）的 title 上传为 "Link(CoF)"，与 musicId 131（"Link"）区分，避免水鱼数据库识别错误。
- **Token 失效**：服务器返回 400 + "导入token有误"时自动清除本地绑定，需重新输入 Token。
- **Token 输入**：输入框支持剪贴板粘贴（Token 极长且不规律，必须支持复制粘贴），不启用自动纠正和建议以避免某些输入法误判为安全键盘模式。

### Q: 落雪查分器同步是什么？如何使用？

**A:** 数据页查分器同步卡片的"落雪同步"按钮，可将本地保存的账号歌曲成绩上传至落雪咖啡屋查分器（maimai.lxns.net），用于记录游玩成绩和查看达成进度。

- **首次使用**：点击"落雪同步"按钮，弹出对话框引导输入个人 API 密钥（在落雪咖啡屋 https://maimai.lxns.net/ 登录后，于"账号详情"中生成）。密钥保存在本地数据库中与 UserID 对应，多账号互不影响。
- **后续同步**：绑定密钥后再次点击会弹出确认对话框，显示将上传的记录数，提供"取消"、"更换Token"、"立即同步"三个选项；确认同步后按落雪官方 API 要求转换本地成绩并上传到 `POST /api/v0/user/maimai/player/scores`。
- **与水鱼同步的差异**：落雪原生支持宴会场曲目（type=utage）成绩上传，标准与 DX 谱面共享同一曲目 ID（DX 谱面 musicId 会取模 10000 转换）；请求头使用 `X-User-Token`，请求体为 `{"scores":[...]}` 对象包裹数组。`musicId=11422` 虽然本地 song name 是空字符串，仍因目录键存在而上传为 `id=1422`、`type=dx`；这里的 `1422` 只属于落雪请求字段，不是本地歌曲 ID 替换。
- **更换Token**：在同步确认对话框中点击"更换Token"按钮，会重新弹出密钥输入对话框。
- **解除绑定**：在设置页删除对应账号数据，会同步删除该账号的落雪密钥绑定记录。
- **Token 失效**：服务器返回 401 时自动清除本地绑定，需重新输入密钥。
- **Token 输入**：输入框支持剪贴板粘贴（密钥较长且不规律，必须支持复制粘贴），不启用自动纠正和建议以避免某些输入法误判为安全键盘模式。

### Q: 数据页歌曲详情的"收录版本"对部分新歌显示为最新版本？

**A:** 数据页歌曲子页的“收录版本”实时读取 LXNS，列表的版本筛选读取生成的静态对照表；两条链路都按当前 musicId 对应谱面类型判断：标准谱取 standard、DX 谱取 dx、宴会场取 utage，不会使用另一种谱面的版本。即使同一 song_id 的谱面在不同版本收录，也会分别归类；例如 1103 的 standard 谱为舞萌DX 2024，11103 的 DX 谱仍为舞萌DX 2021，1301/11301 也是同类情况。游戏内 DX 谱面的 musicId（如新版 Dragoon 的 10367）会通过取模转换为 song_id（367）请求 LXNS；若 LXNS 中该 song_id 存在但对应类型谱面为空（367 的 DX 谱面未收录，只有旧版 standard 谱面），详情页“收录版本”会回退显示为当前最新版本号，而非错误显示同名旧曲的版本。若 LXNS 完全未收录该 song_id（如 11847），则详情页无法打开。标题/艺术家/流派/BPM 仍取自同名旧曲数据——新旧版是同一首歌的不同谱面版本，这些字段相同。

### Q: 系统显示大小设置过大时，歌曲详情的表格会显示异常吗？

**A:** 不会。数据页歌曲详情的物量表和游玩成绩表已适配系统显示大小设置——内容窄时表格撑满可用宽度不留空，内容宽（如调大系统字体后）时自动支持横向滚动，达成率、评级等列内容完整显示不会被挤压。对任意显示缩放比例（100%/125%/150%/200%…）都成立。

### Q: 收藏品列表中的"从整体中随机选择"/"从收藏中随机选择"是什么？

**A:** 这是游戏内"随机"功能的两种特殊设置状态（ID=2/3），不是实际存在的收藏品。数据页收藏品子页和获取收藏品选择器只显示实际存在的收藏品，不显示这两项；但设置收藏品选择器例外，允许用户选择随机装备模式作为装备值；对照表保留它们的 ID 映射，当用户装备了这两个随机状态时（游玩时可选择），账号子页装备预览和已选收藏品列表仍能正确显示名称。

### Q: “批量上传歌曲”是什么？和“修改并上传”有什么关系？

**A:** “修改并上传”是“获取账号数据”页的主开关，“批量上传歌曲”是同一卡片内的子开关。子开关只在主开关开启时显示；关闭主开关时会隐藏并清除批量上传歌曲状态，流程仅获取数据。主开关开启且批量上传歌曲关闭时，获取完整账号数据后进入普通自定义数据配置；两个开关都开启时，获取完整账号数据后才打开批量上传歌曲配置页。配置页的目标选择方式互斥：按版本选择会处理一个或多个版本的并集，按歌曲选择则只处理多选器明确确认的 musicId，不会扩展到同版本其他歌曲；两种方式都把绿/黄/红/紫/白难度和目标成绩条件应用到目标歌曲。歌曲模式不设置收藏歌曲选择器的 30 首上限。每批最多处理 3 张，并通过续关在下一会话重新下载完整数据、回验上一批后继续。白谱仅按实际存在性目录或本次 baseline 的精确 level 4 记录纳入，standard/DX 不互相复用；该目录仅用于批量上传歌曲选谱，与歌曲解锁的 Re:MASTER 条件清单无关。历史 DX 分不参与进度预览或达标筛选，配置页不会为目标歌曲请求 LXNS 物量；实际生成上传成绩时才按批次读取目标谱面物量。DX 百分比表示该局实际 achievement + combo 的连续可达 DX 区间位置，`0%`/`100%` 对应两端。选定合格基础成绩后，百分比只在同一结果中重映射普通 Note 的 CP/P，不会为每个百分比重复运行完整搜索；若当前 achievement 锚点无解，仍会在有限候选内尝试下一个锚点。已有成绩按 combo 等级判断是否达标，新生成成绩则精确保持用户所选 combo。长任务在每轮 baseline、配置返回、零目标完成和 confirmed 登出后的续关前按需续期可信时间；50 秒等待结束后，双 UserLog/UserAll 前要求至少剩余 2 分钟，可恢复的续期通信问题最多重试 5 次且不会提前发送写请求，预算耗尽则安全收尾。当前工程仍包含上一轮成绩未于新会话完整 baseline 中全部生效时的最低规避：直接使用最新数据只为仍未达标项重新随机生成成绩，不会为同一状态反复读取音乐数据；同一目标集合连续 5 轮整组均无进展才中断并提示保存完整诊断日志。

补充：DX 百分比实际映射的是同一份 timing 中“经证明连续可达”的 DX 子区间，并非完整物理可达集合的最小/最大值插值；历史 DX 既不参与进度、达标筛选，也不参与续关回验。按歌曲模式仍只使用明确选择的完整 musicId。

批量上传歌曲开始续关后不依赖初始二维码继续保持有效。上传、登录和登出等单次状态变更请求仍保持单发，结果未知时中断；成绩未生效后的下一轮是重新构建的新 payload，不是重发同一个请求。Title/NTP/PowerOn/LXNS 的可恢复读取问题在初次失败后按 2→4→4→8→12 秒最多重试 5 次，共最多 6 次请求，第 5 次重试仍失败就中断。登出无法明确确认时会保留 Session，供下次手动执行收尾。

### Q: “歌曲成绩清除”会清理哪些成绩？

**A:** 它是批量上传歌曲配置页中的独立互斥操作模式，不读取 achievement、DX、combo 或 sync 的普通批量上传歌曲成绩配置。目标只来自本账号当前会话的完整 baseline 中已经存在的 `(musicId, level)`，不会为未游玩谱面补建记录；每条记录严格写入 `achievement=0`、`comboStatus=0`、`syncStatus=0`、`deluxscoreMax=0`、`scoreRank=0`、`extNum1=0`、`playCount=1`。普通用户/管理员许可证、每批最多 3 条、UserLog/UserAll 单发、confirmed 登出、续关新 token 和完整 baseline 回验仍然有效；回验还会按初始 baseline 的每谱成绩差值核对 userdata 聚合。LXNS HTTP 404 会跳过整首并保留原成绩，其他异常会安全停止。

### Q: “修改并上传”开关有什么作用？

**A:** 该开关位于“获取账号数据”标签页，默认开启，是账号数据修改上传流程的主开关：

- **开启、批量上传歌曲关闭**：获取数据后弹出普通自定义配置页，确认后上传存档
- **开启、批量上传歌曲开启**：获取完整账号数据后进入批量上传歌曲配置和多会话处理流程
- **关闭**：隐藏并清除同一卡片内的批量上传歌曲子开关；获取数据后直接登出，仅更新本地数据，不修改服务器存档

### Q: 日志导出文件在哪里？

**A:** 日志导出时会弹出文件选择对话框，您可以选择保存位置。导出文件为 `.txt` 格式，包含当前任务的配置和运行状态、操作日志、变更详情、最近 10 批 UserLog/UserAll 载荷以及 GameClient/LXNS 网络诊断详情。载荷按批次成组保留，超出后淘汰最早批次，以控制长时间批量上传歌曲的内存占用。APP 内简要日志不会重复列出配置状态摘要；这些信息保留在导出文件的配置快照中。LXNS 诊断正文单次最多采集 10 KiB，文件中会标出总量和截断量。

### Q: 处理过程中可以取消吗？

**A:** 可以。点击**取消**按钮后，应用会在下一个安全检查点停止主业务并尝试登出；如果登出无法确认，Session 会保留，供下次手动执行时继续收尾。批量上传歌曲不会把尚未通过下一会话 baseline 回验的批次误报为完成，也不会在取消后继续发送下一批。

## 注意事项

1. **二维码时效**：有效期 10 分钟，请及时使用
2. **许可证时效**：创建后 1 小时内必须导入；试用许可证从签发时刻起固定有效 2880 分钟，导入时效不顺延有效期
3. **功能票倍数**：5 倍存在风险，建议使用默认的 3 倍（4 倍和 6 倍因游戏 1.55 版本起不再支持，已移除）
4. **发票等待**：固定 20 秒等待，从登录响应成功返回后计时
5. **网络环境**：确保网络连接稳定，如需代理请在系统 WLAN 设置中配置
6. **机厅配置**：仅手动填写机台狗号；区域、店铺和 Title `dateTime` 来自 PowerOn，店铺 ID 会从 PowerOn 十六进制 `place_id` 转换为十进制
7. **时间同步与 PowerOn**：启动时自动 NTP 检测和 PowerOn；执行前必须拥有新鲜可信网络时间和可用 PowerOn 状态。长时间批量上传歌曲任务会在安全边界按需续期，仍不放宽 30 分钟上限；同步/认证期间不能开始执行
8. **存档修改**：请谨慎使用，配置时登录态保持中，请尽快完成配置；保存后若未到上传边界会继续等待，到时自动上传
9. **批量上传歌曲任务**：仅普通用户/管理员许可证可用；配置页互斥提供批量上传歌曲/歌曲成绩清除，按版本或按歌曲选择目标，歌曲模式只处理明确 musicId，不设 30 首上限；每批最多 3 张谱面并依赖 confirmed 登出、续关和完整 baseline 回验。清除模式只处理 baseline 已有 `(musicId, level)`，固定字段清零且 `playCount=1`，并按完整 baseline-relative delta 回验 userdata 聚合；可恢复读取与可信时间续期通信问题仍在初次失败后按 2→4→4→8→12 秒最多重试 5 次，重试耗尽、状态变更结果未知、业务拒绝、授权失效、硬熔断、取消或保护丢失时中断
10. **安全登出**：无论操作成功或失败，应用都会尝试安全登出；异常退出后下次检测到已登录会自动尝试登出
